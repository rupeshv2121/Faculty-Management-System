Key Features

What's inside?

A comprehensive set of features designed to demonstrate real-world web application patterns.

Role-Based Access Control

Three distinct roles — Admin, Faculty, and Student — each with carefully scoped permissions enforced on both frontend and backend.

Session Authentication

HTTP-only cookie sessions with 24-hour TTL, randomly generated 32-byte IDs, and SHA-256 + salt password hashing. No JWT, no complexity.

File-Based Storage

Pipe-delimited flat-file storage (users.txt) intentionally demonstrates core concepts without a database dependency.

Role-Specific Dashboards

Admin sees stats and charts, Faculty sees their profile and colleagues, Students get a search-first view with department browsing.

Full CRUD Operations

Admin can create, view, update, and delete faculty records. Faculty can update their own email and mobile. Students have read-only access.

Live Faculty Search

Real-time search by name, department, or subject, with results shown instantly — no page reload required.

Department Analytics

Bar chart visualizing faculty distribution across departments, with summary stats for total faculty, departments, and students.

CORS & Security

Properly configured CORS with credentials support, input sanitization, and role checks on every protected API endpoint.

Architecture

How It Works

01

Client Request

User visits the app and logs in with their role-specific credentials via the login form.

02

Auth & Session

Server validates credentials, hashes password with SHA-256 + salt, creates an HTTP-only session cookie.

03

API Processing

Express routes check session + role, then read/write from flat-file storage (faculty.txt / users.txt).

04

Role Dashboard

Response is returned to the client and the role-specific dashboard is rendered with real data.
